# Receive Parser Specifications & Analysis (`RECEIVE_PARSER_ANALYSIS.md`)

## Overview
Detailed specification of the receive frame parser in `DeviceCommunicationLibrary.dll`.

## Frame Delimiters & Structure
- **Header Magic**: `0x41 0x48` (ASCII `"AH"`)
- **Footer Magic**: `0x4D 0x49` (ASCII `"MI"`)
- **Minimum Valid Frame Length**: `10 bytes`
- **Control Word (`CTRL`)**: 16-bit Big-Endian. Bit 15 = CRC Enable, Bits 0–14 = Content Length (`2 + Payload length`).
- **Command Opcode (`CMD`)**: 16-bit Big-Endian (Bytes 4–5). Response CMD equals `RequestCmd | 0x40`.
- **CRC Field**: 16-bit field before footer (Bytes `len-4..len-3`). Always `0x0000` when CRC bit is 0.

## Complete Receive Processing Pipeline

```
Raw Bytes from Serial Stream
  │
  ├── 1. SerialPort_DataReceived Event
  │     └── Appends bytes to _receiveBuffer byte array
  │
  ├── 2. ProcessReceiveBuffer()
  │     ├── FindFrameStart() -> Scan for 0x41 0x48 ('AH')
  │     ├── FindFrameEnd()   -> Scan for 0x4D 0x49 ('MI') starting at startIndex + 4
  │     └── Copy delimiter-enclosed slice into frameData byte array
  │
  ├── 3. OnDataReceived(frameData)
  │     └── FIRES DataReceived EVENT IMMEDIATELY (Before parsing or pending requests lookup)
  │
  └── 4. ProcessCompleteFrame(frameData)
        ├── ExtractCmdFromBytes(frameData) -> Extracts 16-bit CMD opcode
        ├── ConcurrentDictionary.TryRemove(cmd, out tcs)
        │     ├── IF Match Found:
        │     │     └── ProcessResponseFrame(...) -> Parse() -> tcs.TrySetResult(responseObj)
        │     └── IF No Match Found:
        │           └── Console.WriteLine("Unmatched CMD=0x{0:X4}...")
```

## Key Findings & Proofs
1. **No Silent Byte Discard**:
   `OnDataReceived` fires BEFORE `ExtractCmdFromBytes`, dictionary lookup, or CRC parsing. If any byte chunk arrives from the serial driver, `OnDataReceived` MUST be called.
2. **True Zero Bytes Delivered**:
   Because `OnDataReceived` is not called and `usbmon` / direct `usbfs` ioctls return `ETIMEDOUT` (errno 110) on EP `0x81` Bulk IN, zero bytes are being generated by the physical device endpoint.
