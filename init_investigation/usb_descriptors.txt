=== ANALYSIS NOTES ===

1. bDeviceClass=0xEF (Miscellaneous) with bDeviceProtocol=1 (IAD) is standard for CDC ACM
   devices that need Interface Association Descriptors.

2. CDC ACM bmCapabilities=0x02 means the device firmware handles:
   - SET_LINE_CODING (bRequest=0x20): sets baud/parity/databits/stopbits
   - GET_LINE_CODING (bRequest=0x21): reads current settings
   - SET_CONTROL_LINE_STATE (bRequest=0x22): sets DTR/RTS
   It does NOT claim SEND_BREAK (bit 2).

3. EP 0x83 (Interrupt IN, 8 bytes, 10ms bInterval):
   This is the CDC ACM SERIAL_STATE notification endpoint, NOT application data.
   cdc_acm driver polls this endpoint for modem state changes (DSR, DCD, RING, etc.).
   Prior investigation observed this endpoint active — that is NORMAL CDC ACM behavior,
   not evidence of application-level data.

4. EP 0x02 (Bulk OUT, 512 bytes): Application → Device
5. EP 0x81 (Bulk IN, 512 bytes): Device → Application

6. No iSerial (iSerial=0): Device has no USB serial number string.

7. bcdDevice=1.41: firmware version 1.41
